# Worklog — Legis SaaS (reconstrução da suíte legislativa)

Projeto: reconstrução da suíte legislativa SaaS (ex-PainelDeskLegis 8.1) conforme
`upload/PROMPT_MESTRE_RECONSTRUCAO_SAAS_LEGISLATIVA.md`, adaptada ao ambiente do sandbox
(Next.js 16 App Router + Prisma/SQLite + mini-serviço socket.io na porta 3003 + gateway Caddy).

Convenções:
- Todas as rotas de API em `/api/v1` (REST, envelope de erro Problem Details).
- Única rota visível: `/` (SPA com troca de módulos no cliente).
- Tempo real: mini-serviço `mini-services/realtime` (porta 3003), padrão outbox transacional
  (tabela `OutboxEvent` lida pelo serviço; cliente conecta em `/?XTransformPort=3003`).
- Ator demo via header `x-actor-id` (RBAC simulado, documentado em ADR-005).
- UI em pt-BR, dark mode, cores institucionais verde/dourado (sem indigo/azul).

Task ID: 2-b
Agent: full-stack-developer (realtime)
Task: Mini-serviço de tempo real (Bun + socket.io, porta fixa 3003) que publica eventos da tabela
`OutboxEvent` para backoffice interno (sala `tenant:{tenantId}`) e portal/telão públicos (sala
`public:{tenantId}`), com envelope `RealtimeEvent` exato do prompt mestre, poller de 500ms,
health check HTTP e graceful shutdown.

Work Log:
- Lidos worklog.md, ADR-003 (tempo real outbox), docs/api-contract.md (seção "Eventos outbox") e
  examples/websocket/server.ts (path '/' obrigatório — gateway Caddy).
- Colunas reais de `OutboxEvent` verificadas via `PRAGMA table_info` (id, tenantId, eventType,
  aggregateId, sessionId, internalPayload NOT NULL, publicPayload, status, createdAt, publishedAt).
  Probe confirmou: Prisma grava DATETIME como epoch millis (INTEGER), mas `publishedAt` texto
  (`datetime('now')`) também é lido corretamente pelo Prisma — update do poller segue a spec.
- Criado projeto Bun isolado `mini-services/realtime/` (package.json próprio, `socket.io@4.8.3`
  dep + `socket.io-client` devDep; NÃO tocou no package.json principal).
- index.ts: http server + `new Server(http, { path: '/', cors: '*', pingTimeout 60s, pingInterval
  25s })`; abertura do banco com `new Database(path, { strict: true })` + `PRAGMA
  journal_mode=WAL` + `PRAGMA busy_timeout=2000`.
- Handshake/subscribe: evento `subscribe {tenantId, scope}` valida tenantId (regex cuid) e scope
  ('internal'|'public'), entra em `tenant:{id}`/`public:{id}`, confirma com `subscribed {tenantId,
  scope, rooms}`; `subscribe_error` em payload inválido. Fallback: `auth` do handshake também
  inscreve (compatível com use-realtime.ts da Task 1, que envia auth E subscribe; join idempotente).
- Poller (500ms, lote ≤ 50, mais antigos primeiro): monta envelope `RealtimeEvent`
  (schemaVersion 1; `origin`/`aggregateVersion`/`correlationId` ERGUIDOS do payload e REMOVIDOS da
  cópia emitida; occurredAt ISO — conversor cobre epoch millis do Prisma e texto SQLite UTC);
  emite envelope interno para `tenant:{id}` e envelope público (payload sanitizado) para
  `public:{id}`; marca `published` + `publishedAt=datetime('now')` com retry 3x/100ms para
  SQLITE_BUSY. Sem assinantes também marca published (telão reconstrói por snapshot — ADR-003).
- Health check: com path '/' o engine.io intercepta TODAS as requisições HTTP (check
  `'/' === req.url.slice(0,1)`), então o handler de `/health` foi INTERPOSTO na frente do listener
  do engine.io (guarda listeners de request, registra o próprio, repassa o resto) — validado com
  curl direto e via gateway (`/health?XTransformPort=3003` → 200 {"ok":true}).
- Logging JSON conciso (conexões, inscrições, lotes publicados com eventType/tenant/salas
  ocupadas, erros). Graceful shutdown SIGTERM/SIGINT fecha io+http+db.
- Descoberta operacional do sandbox: `nohup ... &` morre quando o comando Bash termina (kill da
  árvore de processos). Solução: orfanar via subshell `(nohup bun run dev > service.log 2>&1 < /dev/null &)`
  → PPID 1, sobrevive igual ao dev do Next.js. Serviço rodando (PID verificado, uptime crescente).
- test-client.ts: pega tenantId real do banco, conecta clientes internal E public, emite subscribe,
  insere OutboxEvent 'test.ping' pending, valida envelopes recebidos (erguimento/remoção dos
  campos auxiliares, payload público sanitizado), confere status 'published' + publishedAt no
  banco, limpa o evento de teste. Corrigida race de 'connect' (socket.connected check).
- Teste ponta a ponta executado 2x: exit 0 nas duas, 24 verificações ✔ (envelope interno e
  público, published no banco, limpeza — 0 eventos test.ping remanescentes). Latência observada
  insert→publish ≈ 200ms (poller 500ms).

Stage Summary:
- Entregue: `mini-services/realtime/` (package.json, index.ts, test-client.ts, service.log),
  servindo em ws://localhost:3003 (path '/'), compatível com o hook `use-realtime.ts` da Task 1
  (`io("/?XTransformPort=3003")`, auth + subscribe, dedup por eventId no cliente).
- Teste real executado: `bun test-client.ts` → sucesso (2 rodadas), health check 200 direto e
  via gateway, handshakes websocket confirmados nos logs.
- Riscos/limitações: (1) entrega ≥1 vez — dedup por eventId é responsabilidade do cliente (já
  implementado no hook da Task 1); (2) eventos publicados sem assinantes não são reentregues
  (telão reconstrói por snapshot via /api/v1/public/live — documentado no ADR-003); (3) polling
  de 500ms adiciona latência ≤ ~1,2s no pior caso; (4) se o sandbox reiniciar, o serviço precisa
  ser religado com o comando de orfanamento documentado acima (simples `nohup ... &` não
  sobrevive ao término do comando Bash); (5) escopo público não exige autenticação (por design —
  dados públicos sanitizados), validação de tenantId por formato cuid apenas.
